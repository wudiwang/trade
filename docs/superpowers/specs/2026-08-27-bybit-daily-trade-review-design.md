# Bybit 每日交易电影与 AI 纪律复盘设计

日期：2026-08-27

## 目标

建立一个本地只读复盘系统。用户以后只需说“复盘 Bybit 今天/最近24小时的真实交易”，系统即可：

1. 拉取 Bybit 真实成交和账户流水；
2. 按北京时间自然日还原完整交易回合；
3. 计算真实净盈亏、费用、收益率和交易统计；
4. 在 1m/15m K 线标出进场、加仓、减仓和平仓；
5. 依据用户纪律和探索因子逐笔给出证据化复盘；
6. 生成手机可读的“交易电影”页面、摘要图片和 Telegram 消息。

本系统属于本地研究室，不接管 Bybit 下单，不修改 Binance/VPS 实盘系统。

## 已选方案

采用“确定性账本 + 规则证据 + AI 解释”三层设计。

- 确定性账本负责钱和成交，AI 无权修改数字。
- 规则证据负责可计算事实，例如是否处于 24h 涨幅榜、15m 是否形成低高点/低低点、
  1m 是否出现放大实体、是否接近前高或 POC。
- AI 只把事实组织成复盘语言，区分硬纪律、参考因子和未知项，禁止补造不存在的原因。

不采用“把原始成交直接丢给 AI”方案，因为它不能稳定重建加减仓、费用和跨日持仓；也不采用
“只做统计表”方案，因为它无法满足逐图回看和纪律改进的目标。

## 安全边界

- Bybit API Key 必须是 `readOnly=1`。系统启动时调用官方 Key 信息接口验证；若为读写 Key，立即拒绝运行。
- 只调用查询接口，不实现或导入任何下单、撤单、转账、提现方法。
- 不读取、显示、记录、提交或通过 Telegram 发送 API Key/Secret。
- 凭据由用户在系统外配置；仓库仅声明环境变量名称，不写入 `.env`。
- 原始私有数据、生成报告和图形默认保存在本地忽略目录，不提交 Git。
- Telegram 只发送复盘报告，不附带任何可交易按钮。

## 时间口径

- 时区固定为 `Asia/Shanghai`。
- 完整日报窗口为北京时间 `00:00:00.000` 至次日 `00:00:00.000`，左闭右开。
- 当天尚未结束时显示“今日截至当前”，不能伪称完整日报。
- “最近24小时”是独立滚动窗口，不与自然日报混用。
- 交易回合可跨越日界线；日报财务只统计窗口内发生的账户变化，图形则补齐该回合的完整前后文。

## Bybit 数据源与财务真值

使用 Bybit V5 官方接口：

- `/v5/user/query-api`：验证 Key 为只读。
- `/v5/execution/list`：真实撮合点、数量、价格、Maker/Taker 和执行费用。
- `/v5/order/history`：订单意图、订单类型、触发单和仓位方向辅助信息。
- `/v5/position/closed-pnl`：平均进出价、已结盈亏、杠杆、开平手续费。
- `/v5/account/transaction-log`：现金流、资金费、手续费和账户变化。
- `/v5/account/wallet-balance`：运行时账户权益快照。
- `/v5/market/kline`：1m/15m K 线。
- `/v5/market/tickers`：当时可获得的市场 24h 波动参考；历史榜单缺失时必须标为未知。

所有分页接口必须遍历 `nextPageCursor`，使用官方唯一标识去重，并保存原始响应摘要以便审计。

### 净盈亏

统一账户每日交易净变化以交易相关账户流水的 `change` 为财务真值：

`change = cashFlow + funding - fee`

报告分别显示：

- 已结交易盈亏；
- 手续费；
- 资金费；
- 交易净盈亏；
- 非交易转入/转出（单列，不计入交易表现）；
- 期末未实现盈亏（快照项，不混入已结净盈亏）。

若账户流水与已结盈亏明细无法对账，报告状态为“数据不一致”，展示差额并禁止生成确定性结论。

### 收益率

- 日账户收益率：交易净盈亏 ÷ 日初账户权益。
- 首次接入无法得到可靠日初权益时，用账户流水重建日初现金余额并明确标注“重建口径”；
  从接入后的下一天开始使用每日 00:00 权益快照。
- 单笔价格收益率：按方向计算平均进出价的标的价格变动。
- 单笔保证金 ROE：使用已结盈亏记录中的杠杆和累计进场价值估算；交叉/组合保证金无法唯一归属时，
  标注为“估算”，不能伪装成 Bybit UI 的精确 ROE。

## 交易回合重建

原始单位是 execution，不是 order，更不是完整交易。重建器按 `account/category/symbol/position side`
处理有序成交：

- 净仓从 0 变为非 0：回合开始；
- 同方向成交：加仓；
- 反方向但未归零：减仓；
- 回到 0：回合结束；
- 穿越 0：先结束旧回合，再开始反向新回合；
- 未归零：标记为持仓中，不计算完整胜负。

优先使用订单历史和仓位标识区分对冲模式；无法可靠区分时停止合并并标记人工复核，不能把多空两条腿混成一笔。
Closed PnL 用作财务和均价对照，而不是替代执行点。

## 用户纪律模型 v1

第一版聚焦“高位反转做空”，不把尚在摸索的经验强行硬编码。

### 硬纪律

硬纪律只包含用户明确认可、且可以核对的项目：

- 标的是高波动候选，来自 24h 涨跌幅榜、自选观察或预先记录的反转候选；
- 主要结构判断级别是 15m；
- 左侧尝试必须是轻仓；
- 每笔交易必须能识别风险边界；没有止损或风险边界时标红；
- 复盘必须区分计划内交易与临时冲动交易。

“轻仓”的数值阈值暂不替用户假设。系统先显示该笔最大名义仓位、估算保证金、占账户权益比例和
相对当日中位仓位倍数，AI 只标记偏离程度；积累样本后再由用户确定硬阈值。

### 结构证据

- 15m 做空趋势转换参考：反弹高点未突破前高，随后低点跌破前低。
- 转换后再次回抽到此前显著高点附近，是顺势做空的参考位置。
- 结构失败或未完成必须明确显示，不能因为交易盈利就倒推为合规。

### 探索因子

以下只做证据卡和长期统计，不单独判违规：

- 1m 单根大实体与前序 K 线相比显著放大；
- 1m 三根 K 线价格真空/FVG；
- 极端上涨末端继续加速；
- 上涨速度衰减、无法继续显著创新高、上影线或首根阴线；
- 接近前高、POC 或其他显著成交密集区；
- 15m 转换区域与上述因子共振。

每个因子保存 `present/absent/unknown` 和原始数值。`unknown` 不能按 `absent` 处理。

## AI 复盘输出

每个交易回合输出：

- 结果：净盈亏 U、价格收益率、估算 ROE、手续费、资金费、持仓时间；
- 操作电影：所有 execution 标记和仓位曲线；
- 硬纪律：逐条通过/违反/未知及证据；
- 探索因子：出现、缺少、未知；
- 结论：`合规`、`部分合规`、`冲动交易`、`严重变形` 四级；
- 原因：最多三条，每条必须引用时间、价格、周期或仓位数据；
- 改进：只给一个下一次可执行动作，避免事后诸葛亮式长篇建议。

“手法偏离度”与“纪律合规度”分开。手法偏离度比较最近 30 个完整回合的币种波动、方向、仓位、
持仓时间、进场时段和加减仓习惯；它只说明“不像平时”，不说明对错，也不能把坏习惯变成纪律。

AI 生成失败时，确定性统计和规则证据仍须完整展示；报告标记“AI 解读未生成”，不阻塞日报。

## 每日总报告

顶部战绩：

- 交易净盈亏 U、账户收益率、已结盈亏、手续费、资金费、未实现盈亏；
- 完整回合数、胜率、盈亏比、Profit Factor、最大单笔盈利/亏损；
- 做多/做空、币种、时段和仓位分布；
- 合规/部分合规/冲动/严重变形数量。

日报正文：

1. 今日一句话结论；
2. 盈利来自哪里；
3. 亏损发生在哪里；
4. 纪律做得最好的一笔；
5. 最需要复看的变形交易；
6. 所有交易按时间排列的“电影”；
7. 明天只改一件事；
8. 数据完整性与未知项。

不能把盈利等同于正确，也不能把亏损等同于违规。纪律判断和结果判断必须分栏。

## 页面与 Telegram

本地研究页面新增“每日复盘”入口：

- 日期切换和“今天/昨天/最近24小时”；
- 顶部战绩卡；
- 时间轴；
- 每笔交易 1m/15m 双图切换；
- 播放上一笔/下一笔，形成回看电影体验；
- 点击 execution 查看成交价、数量、费用和订单类型；
- 纪律证据与 AI 结论并排显示；
- 支持对 AI 结论标记“同意/不同意”并写下用户复盘，供后续规则迭代。

Telegram 发送一条摘要和若干合成图：首图为总战绩，后续每张包含 2–4 个重点交易；附本地/公网报告链接。
若图片发送失败，降级为文字摘要和 HTML 文件，不重复刷屏。

## 存储与可重复执行

建议新增本地 SQLite 表或独立只读研究数据库：

- `bybit_sync_runs`
- `bybit_executions`
- `bybit_orders`
- `bybit_transactions`
- `bybit_closed_pnl`
- `bybit_equity_snapshots`
- `trade_episodes`
- `trade_episode_factors`
- `daily_trade_reviews`
- `review_feedback`

原始记录以 Bybit ID 为唯一键幂等写入；同一天重复生成会更新同一日报，不重复计数或重复推送。

## 自动运行与对话触发

- 北京时间每日 00:05 同步上一自然日，等待交易所流水落库后生成完整日报。
- 00:15 对仍不一致的账本自动重试一次；仍不一致则只发送异常提醒。
- 用户随时可以请求“今天截至当前”“昨天”或“最近24小时”。
- 自动任务创建前必须确认本机/运行主机能安全访问只读凭据；凭据缺失时任务保持禁用。

## 测试与验收

必须覆盖：

- 北京时间日界线与夏令时无关；
- 分页、重复 execution、同毫秒多撮合；
- 加仓、减仓、分批平仓、反手、跨日和未平仓；
- 单向/对冲模式；
- Maker 返佣、Taker 手续费、正负资金费；
- 转入转出不计入交易表现；
- 交易流水与 Closed PnL 对账失败；
- 1m/15m 图形无未来数据；
- AI 超时或输出无效时的确定性降级；
- Telegram 图片失败时降级；
- Key 非只读时拒绝运行。

验收时使用合成数据先通过测试，再用用户指定的一天做只读实盘对账。只有用户确认日报中的成交、费用和净盈亏
与 Bybit 页面一致，才允许启用每日自动发送。
