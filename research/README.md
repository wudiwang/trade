# 研究档案（灵感库）

这里存的不是代码，是**思考的链路**：一个想法从哪张图冒出来 → 中间验证了什么 → 被什么打脸 → 最后剩下什么。

半年后回头翻，你要能一眼看出"我当初为什么信这个，后来为什么不信了"。

## 两类东西

| 类别 | 位置 | 是什么 |
|---|---|---|
| **交易策略** | `ideas/<序号>-<slug>/` | 可以被回测证伪的具体打法。有原图、有假设、有验证链路。 |
| **交易准则** | `principles/P<n>-<slug>.md` | 从多次实验里沉淀出的原则。不针对某个形态，而是关于"怎么做研究、怎么不骗自己"。 |

策略会死（大部分都会），**准则会活下来**。这就是分开存的原因。

## 一个灵感长什么样

```
ideas/001-fvg-retest-1m-entry/
  idea.md        # 出发点(你的原话) + 这张图发生了什么 + 假设 + 待明确的定义 + 数据前提
  timeline.md    # 追加式研究日志: 每做一步就在最上面加一条(含回测数字和结论)
  charts/        # 原始截图(你当时看到的那张图, 原样保存)
  backtests/     # 每轮回测的结果(可选)
```

`idea.md` 的 frontmatter 里 `status` 走这条线：

```
灵感 → 立项 → 回测中 → 已验证 / 已证伪 → 上线
```

**"已证伪"不是失败，是资产。** 它告诉你哪条路不用再走第二遍。

## 怎么归档

跟 Claude 说「把这个存进灵感库」，或者发一张图 + 一段想法。Claude 会：

1. 建 `ideas/<序号>-<slug>/`，把原图存进 `charts/`
2. 把你的原话**一字不改**记进 `idea.md`（不要让总结替换掉你当时真实的想法）
3. 列出必须由你拍板的定义（模糊的地方要写明"待定"，不能替你假设）
4. 之后每做一次回测/证伪，往 `timeline.md` 顶部追加一条
